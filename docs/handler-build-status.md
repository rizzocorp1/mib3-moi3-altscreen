# V12 auxiliary keyframe recovery — awaiting vehicle motion test

V11 produced the first user-confirmed Google Maps picture on the cluster, but it stayed frozen while routes/apps were changed. The sender continued:2807 authenticated access units and14923 observed outgoing packets, with no observed sequence discontinuities or send errors. Only one IDR was received during roughly2.5minutes. Native VW video used profile66/Baseline and phone video profile100/High, both level31. This is a compatibility difference to investigate, not proof of incompatibility; a real custom picture was displayed. App switching also leaves UI-selection behavior unisolated.

V12 retains the v11 transport/video path and adds a bounded auxiliary-only forceKeyFrame request after authenticated encoder handoff: at most once per two seconds,90 attempts per stream. The request carries the advertised auxiliary UUID; dictionary readback rejects missing/incorrect scoping. It does not use the untargeted primary-screen helper, change codec labels, re-encode video or force an app/UI selection.

The matching factory SendCommand ABI and public session-queue accessor were inspected read-only. Requests are enqueued asynchronously on the public session queue; native command serialization uses a separate event queue and asynchronous HTTP send. No receiver thread waits for the command operation. Retained session/request objects, generation cancellation, one current pending request and a four-job global bound cover teardown races. Native submission errors retain video. Command status is not a phone acknowledgement: returned IDR counts and visible motion are the acceptance evidence. [DiPlay's AirPlaySession](https://github.com/shihabal3amri/DiPlay/blob/main/shared/src/main/java/com/shilapi/xcertplay/airplay/AirPlaySession.kt) is the primary reference for UUID-scoped auxiliary command shape.

Tests cover pre-grant rejection, auxiliary scope, missing params, allocation/retain failure, rate/coalescing limits, native errors, stale/security cancellation, retained lifetime and invalidation while a native sender is blocked. Logging shutdown is serialized against in-flight callbacks. Bounded H264 NAL/AUD counters and wire AUD metadata add format evidence without recording picture data. Existing authentication/queue/teardown, outgoing VLAN capture, discovery, transport, recovery/systemd and H264 decode checks remain.

One parked test keeps Google Maps active throughout, with an actual route on the main CarPlay screen; no app switching. The target is continuous/renewed cluster updates. If requests produce new IDRs but no motion, codec/format compatibility or display behavior remains unresolved. If the phone sends no new IDRs, command delivery/scoping remains unresolved. See altscreen-map-v12.md.

The brief old image during reboot is consistent with retaining the last decoded picture until native output resumes. The user reported stock behavior returning; that observation does not establish a full vehicle rollback. New v12 assets/markers preserve previous evidence. No complete map/motion success is claimed.

Only reviewed source/tests/scripts/docs are published to the user's fork. Raw reports, source tags, unique identifiers, snapshots, firmware-derived binaries, ZIPs and backups remain private. No upstream-author changes or merge. Known speech resets remain and startup recovery is narrow rather than a complete vehicle backup.
