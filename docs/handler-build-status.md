# V9 authenticated video handoff — awaiting vehicle validation

V8 established the auxiliary TCP connection on a factory-permitted port, parsed video configuration and authenticated a valid H264 IDR. The root collector reported encoder grant creation, but the handler never logged forwarding a frame. The user reported normal CarPlay and tested multiple map apps; app transitions may explain some stream restarts. The prior report lacked per-stream teardown and grant-read diagnostics, so the exact causal sequence is unresolved.

V9 corrects the production hook to match MU0841's stream-scoped teardown: partial primary/audio teardown preserves the auxiliary receiver and retained pairing, auxiliary teardown stops that receiver, and full session teardown clears session security. It retains an authenticated opening GOP in bounded RAM (16 MiB/256 access units) while root transfers encoder ownership. A 100 ms input poll releases that GOP after grant validation without requiring another keyframe. Authentication failure, configuration change, teardown and buffer limits discard pending video. Plaintext video is never persisted.

The matching factory transport uses program 1 and transport-stream ID 100, rather than the prior code's reversed values. V9 also matches the factory RTP identifier, millisecond RTP clock and six-slot datagram sizing, retaining standards-valid PES/PCR timing. See mu0841-transport-profile.md for evidence and limits. No firewall or SMACK rule is changed; the permitted auxiliary port range and recovery-first RAM copy remain.

New counters distinguish authenticated input, valid IDRs, buffered release, muxing, successful UDP sends and send failures. Grant errors and bounded read-only displaymanagement/transport diagnostics aid the next hardware check. A new v9 stage and marker protocol preserve old assets and avoid trusting v8 markers. No cluster rendering success is claimed.

Tests cover typed partial/full/unrelated teardown and native argument preservation, delayed grant with no second keyframe, actual authenticated TCP reception through the production gate, buffer limits/discard, factory transport fields/CRCs and IPv4/IPv6. Existing security, metadata, explicit dependency, one-shot recovery, root handoff, systemd and H264 decode checks remain. Host and static checks cannot prove on-car display routing or rendering. See altscreen-map-v9.md for the single parked test.

Only reviewed source/tests/scripts/docs are published to the user's fork. Raw reports, unique device identifiers, capability snapshots, firmware-derived binaries, install ZIPs and backups remain private. The original author's repository is unchanged. Known speech resets remain and startup recovery is not a complete vehicle backup.
